## 1. 这是什么

一个 **Windows 优先、开源、轻量** 的桌面播客客户端。

- **定位**：通用 RSS 播客客户端。核心能力（订阅、播放、进度）**不依赖任何第三方服务**。
- **不做**：不做推荐信息流、不做评论、不做社交、不做付费、不做内容转存。
- **对标视觉**：小宇宙（取其视觉语言，不取其信息架构）。
- **性能目标**：冷启动 <1.5s，空闲 <120MB，安装包 <15MB。

**判断一切设计争议的最高准则**：
> 把网线拔了、把 Apple 的 API 拉黑，应用还应该能完整使用（除了发现页）。

## 6. 内容源规则（合规红线）

### 6.1 允许的三个端点（只有这些）

```
搜索    GET https://itunes.apple.com/search?term={q}&media=podcast&country=cn&limit=50
详情    GET https://itunes.apple.com/lookup?id={collectionId}&entity=podcast
榜单    GET https://itunes.apple.com/{cn|us}/rss/toppodcasts/limit=100/json
类目    GET https://itunes.apple.com/WebObjects/MZStoreServices.woa/ws/genres?id=26
```

- **`country` 默认 `cn`**（参考实现的 bug 就是这里默认了 `us`，导致中文搜索命中美国区）
- 目录只用来"发现 + 取 feedUrl"，**音频一律从节目自己的 RSS/CDN 拉，不经过 Apple**
- 限流约 20 req/min/IP，超了 403。缓存策略：
  搜索结果 24h、榜单 6h、lookup 结果永久（feedUrl 基本不变）、类目树永久

### 6.2 硬禁止

- ❌ 爬任何网页（小宇宙、喜马拉雅、Apple 网页版都不行）
- ❌ 逆向私有接口、模拟登录
- ❌ 镜像/转存节目内容
- ❌ 把 Apple 返回的节目信息当自有数据长期存储（只存 feedUrl 和必要的展示字段）

把这段复制进 `src-tauri/src/core/sources/mod.rs` 的注释里，
**未来任何人（包括 AI）想"顺手"加个源，先读这一段**。

### 6.3 降级要求

Apple 不可达时：

- 发现页显示"暂时无法连接目录服务，你可以粘贴 RSS 链接或导入 OPML"
- **其余所有功能正常**，不弹错误、不阻塞启动
- 已订阅内容的刷新、播放完全不依赖 Apple

## 8. 数据模型

完整建表脚本见同目录 `001_init.sql`，**直接拷进 `src-tauri/migrations/001_init.sql`**。

九个要点（每条都是踩过坑换来的）：

1. **`podcast` 表就是订阅列表**，不存在独立的"订阅关系表"。
   `subscription` 只存可选配置和 ETag 缓存。（参考实现的 `podcastSubscription` 实测是 0 行）
2. **`episode.duration_ms` 是毫秒**。RSS 里的 `itunes:duration` 是 `"1:26:54"`，
   解析成秒后**必须 ×1000**。（参考实现这个字段存的是秒，迁移时有陷阱）
3. **每个连接都要 `PRAGMA foreign_keys = ON`**。SQLite 默认关闭，
   参考实现因此攒了 1065 条孤儿进度记录。
4. **`episode.id` 用 `{feedUrl}:{episodeUrl}`**，刷新去重用 `guid`。
5. **`queue_item.episode_id` 允许为空**，用户会往队列里塞裸音频 URL（实测存在）。
6. **`download_task` 只存文件名，不存绝对路径**。
7. **`play_state.finished` 是粘性位**：>98% 置 1，重听也不回退。
8. **`podcast` 有 `custom_title` / `skip_intro_sec` / `skip_outro_sec`** 三个字段，
   参考实现有但没做成 UI，这次要真的做。
9. **`favorite` / `history` 是独立表**，不要砍成 episode 上的字段——
   它们需要独立时间排序，且要能扛住刷新清理。

## 10. 音频方案

**主方案：HTML5 `<audio>`**（WebView2 就是 Chromium，播客格式全覆盖）

| 需求 | 实现 |
|------|------|
| 倍速 0.5–3.0 不变调 | `audio.playbackRate` |
| 音量增强 >100% | WebAudio：`createMediaElementSource` + `GainNode` |
| 进度 | `timeupdate` 事件（约 4Hz） |
| 睡眠定时 | `setTimeout` + `pause()` |
| 章节跳转 | `audio.currentTime = chapter.start` |

### 三个必须提前处理的问题

1. **后台定时器被节流**：窗口隐藏时 JS 定时器会降频。
   对策：进度上报挂在 `timeupdate` 上（事件驱动不受节流影响），
   再加 Rust 侧定时器每 5 秒兜底 flush。
2. **窗口不能 destroy**：托盘最小化用 `window.hide()`，
   绝对不要 `close()` / `destroy()`，那会销毁 WebView 导致音频中断。
3. **Range 支持**：CDN 不支持 Range 时 seek 会重下整个文件。
   检测到就整集下到本地再播。

### 媒体键（M5，先验证再实现）

**优先方案**：`navigator.mediaSession`。Chromium 在页面有真实媒体播放且设置了
`mediaSession.metadata` 时会自动注册 Windows SMTC，硬件媒体键可能**免费可用**。

```ts
navigator.mediaSession.metadata = new MediaMetadata({ title, artist, artwork: [...] });
navigator.mediaSession.setActionHandler('play', () => audio.play());
navigator.mediaSession.setActionHandler('nexttrack', () => next());
```

**M2 阶段就要实测这一条**。不行再退到 `tauri-plugin-global-shortcut`，
再不行才上 `windows` crate 的 SMTC。**不要一上来就写 JNA 那种全局钩子。**
（参考实现用 `WH_KEYBOARD_LL` 低级钩子，坑很多且容易被杀软拦）

## 13. 关键流程

### 刷新（并发是重点）

```
读 subscription → 筛 last_checked 超过 10 分钟的
  → Semaphore(3) 限制并发
  → GET feedUrl，带 If-None-Match / If-Modified-Since
      ├ 304 → 跳过（不解析，省 CPU）
      └ 200 → feed-rs 解析 → 按 guid 比对 → 新集 is_new=1 → 更新缓存头
  → emit refresh-progress
```

**首次抓取**：库中该 origin 无任何单集时，全部入库但 **`is_new = 0`**
（当基线，避免一次冒出几百条未读）。

**清理策略**：刷新后清理过期单集时，以下三类**只更新不删除**——
被收藏的、有播放进度的、在队列里的。其余每个 feed 保留最新 300 条。

### 播放与进度

```
点某集 → audio.src = url; playbackRate = 设置; play()
       → 从 progress_get 拿 position，audio.currentTime = position
timeupdate（4Hz）→ 更新 UI（纯前端，无 IPC）
               → 每 5 秒节流：progress_save
暂停/切集/退出 → 立即 flush
pos/dur > 0.98 → progress_finish（置 finished=1，粘性）
```

### 下载

```
建 task(pending) → 有断点则 Range: bytes=<received>-
  ├ 206 → 追加写
  └ 200 → 服务端不支持续传，删文件重下
流式写入 + 令牌桶限速 → 每 500ms emit download-progress
```

## 14. 已知坑（Tauri 2 实操）

1. **中文 `productName` + ASCII `mainBinaryName`**：两个都要设，否则要么安装目录是
   一串英文，要么进程路径含中文导致更新失败。
2. **`beforeDevCommand` 的端口要和 `devUrl` 一致**（Vite 默认 5173，Tauri 模板用 1420，
   在 `vite.config.ts` 里 `server.port = 1420` + `strictPort: true`）。
3. **dev 模式窗口关闭 ≠ 应用退出**，测托盘行为要用 `pnpm tauri build` 出来的版本。
4. **rusqlite 的 `bundled` 让首次编译变慢**（约 1–2 分钟），别以为卡死了。
5. **`feed-rs` 对脏 XML 容忍度有限**：遇到解析失败要 catch 并降级到"只用正则取
   `<item>` 的 title/enclosure"，不要整条订阅失败。
6. **`reqwest` 的 rustls 不读系统证书库**，企业代理环境下可能握手失败，
   需要 `rustls-native-certs`。个人环境一般不用管。
7. **NSIS 打包首次会下载 NSIS 工具链**，国内网络可能超时，需要配代理或用镜像。
8. **Svelte 5 的 runes 在 `.svelte.ts` 文件里才能用 `$state`**，
   普通 `.ts` 文件里不能用（会报编译错误）。
9. **不要用 `window.close()` 做托盘最小化**，会销毁 WebView 导致音频中断。

## 15. 旧数据迁移（M1）

老库：`C:\Users\<你>\.podara\podara.db`（38.5 MB）

**形态**：设置页 →「存储」→「从旧版 Podara 导入」，图形化，不做命令行。

**五条安全要求**：

1. 只读打开：`file:...podara.db?mode=ro&immutable=1`
2. 先 dry-run 出报告，确认后再写：
   ```
   将导入：订阅 21 · 单集 4430 · 进度 5 · 历史 14 · 队列 3
   将跳过：孤儿进度 1065 · 空进度 5488
   ```
3. 单事务写入，失败全部回滚
4. 目标库非空时按 `origin`/`id` upsert，**新库进度优先**
5. 完成后写 `import-report.json` 到数据目录

**字段映射要点**（完整表见旧仓库 `docs/技术设计细化.md` 第十三章）：

- `podcast` → `podcast`：**订阅就是这个表**；`overrideTitle`→`custom_title`、
  `skipBeginning/Ending`→`skip_intro_sec/skip_outro_sec`

  **`duration × 1000`**
- `podcastEpisodePlayState` → `play_state`：**只迁 `positionMs > 0` 的**

- `playerQueueItem` → `queue_item`：匹配不上 episode 的写 `raw_url`

## 17. 参考实现里值得抄的具体做法

这些是原作者的"对的部分"，重写时直接继承思路，但用新架构实现：

1. **订阅页做成跨播客的「最新更新」聚合流**（不是按播客分组的列表）——
   播客是"追更"场景，聚合流才对。
2. **首次抓取全部标为已读**，避免新用户一进来 500 条未读。
3. **`finished` 粘性位**：听完再重听不被打回未听完。
4. **ETag / If-Modified-Since 条件请求**：省流量也省 CPU（304 直接跳过解析）。
5. **刷新并发限制在 3**：20 个频道 3 并发比全并发更快完成（不抢带宽）。
6. **下载用 Range 续传 + 令牌桶限速**。
7. **播放队列手动添加**，不自动塞整档节目（原作者后来改的，是对的）。
8. **封面取主色**用于 UI 强调色。

## 18. 参考实现里必须避开的坑

1. **不写巨型文件**。参考实现 `App.kt` 2476 行 + `PlayerUI.kt` 1748 行 = 全项目 27%。
2. **不把 SQL 散在各处**。全部收进 `core/db/`。
3. **不用无类型的 String Map 传递数据**（参考实现 UI 文案全走 `Map<String,String>`，
   没有编译期校验）。
4. **不留死字段**。`enableNotifications` / `Genre` 枚举 23 项 / `SyncManager`
   都是"有数据层没 UI"的半成品，这次要么做完要么不写。
5. **要加单实例锁**（`tauri-plugin-single-instance`），否则开两个实例会抢数据库。
6. **不要在代码里散落 `ALTER TABLE`**，用 `migrations/*.sql` + `schema_version`。
